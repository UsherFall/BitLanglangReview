# 回溯复盘切周期视图回右缘：锚定时机修复 + 焦点单不跨周期

## Goal

回溯复盘模式下切换周期后，视口必须落在光标右缘（能看到最新已揭示的 K 线），而不是停在旧数据锚定的错误位置或焦点单的开仓点。

## Background（用户现场 11/04）

- 用户开仓后（且点过单子行，处于焦点单态）切换周期，期望视图拉到右缘；实际视图不落在右缘。
- 两条独立成因：
  1. **锚定时机缺陷**：切周期那一帧渲染 effect 拿旧周期 `renderedCandles` 就把 `initializedRangeKeyRef` 消费掉并 `timeToIndex` 锚定；新周期数据落地后不再重锚。旧周期里回看/翻页加载的历史越多，索引偏移越大，轻则停中段、重则整屏空白。
  2. **焦点单跨周期存活**（10/29 R3 既有设计）：切周期不清 orderFocus，新周期重新取窗锚到开仓点。用户产品观：回溯模式以右缘为默认，"看单子跳开仓点"是交割单复盘的模式语言，回溯里切周期应回右缘。

## Requirements

- R1 无焦点单切周期 → 视口锚定光标右缘（右侧 10 根缓冲，`anchorViewportToCursor` 语义）——这是修复锚定时机缺陷后的稳定行为，不因切周期前回看/翻页量而偏移。
- R2 有焦点单切周期 → 清除焦点单（含剪刀/开仓点前视图、单子行高亮），活动数据集回游标数据集，视口锚定光标右缘。焦点单不再跨周期存活。
- R3 交割单复盘模式（非回溯）的切周期行为不受影响。
- R4 焦点点单、模拟单库跳回合、「回到光标」等既有行为不回归。

## Acceptance Criteria

- [ ] AC1 开仓后（无论是否点过单子行）切换周期：视口落在光标右缘，能看到最新已揭示 K 线；单子行 `active` 高亮与剪刀态清除。
- [ ] AC2 切周期前在旧周期大量回看/翻页加载历史，切周期后视口仍准确落右缘（不落中段、不整屏空白）。
- [ ] AC3 切周期后焦点单行不再 `active`；再点该单子行可重新聚焦归位（token 递增，10/29 用户现场场景仍成立）。
- [ ] AC4 `tests/app-free-replay.test.tsx` 中「keeps the order anchor across timeframe switches」改写为新契约（切周期 → 光标锚定 + 焦点清除），并补 AC2 场景的锚定时机回归测试。
- [ ] AC5 全量测试通过（`tests/level-alert-parity.test.ts` 既有失败除外——缺 pool 数据目录，与本任务无关）。

## Non-Goals

- 不动焦点单取窗/拖动/推迟渲染机制本身（11/04 焦点单拖动任务已修）。
- 不动切周期时 K 线数据加载/缓存/洞自愈链路。
- 不做「切周期保留焦点」的开关配置。
