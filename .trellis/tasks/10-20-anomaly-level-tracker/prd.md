## 用户 2026-10-20 的原话（需求来源）

> 我觉得这个扫描还是找异动粗筛的思路吧，找到异动拉升然后我标出压力位，后续扫描就跟我说今天涨跌幅多少距离压力位还有多少

回答确认的三件事：

| 问题 | 用户的选择 |
|---|---|
| 流程 | **对，就是这三步**：粗筛给「异动拉升 + 那个区间」→ 用户标压力位 → 每天报涨跌幅 + 距离 |
| 「距离压力位」口径 | **上方最近的一条**（现价在几条线中间时，报上方最近那条） |

## Goal

**扫描器不再判断“能不能做”，只做两步机械劳动：**

```
第 1 步  粗筛：找出「最近有一段异动拉升」的币，并给出那段拉升的区间
              —— 不判断顶、不判断收敛、不判断好坏
第 2 步  用户：在这段拉升的图上标压力位（水平线）
第 3 步  每天：对该币报两个数 —— 当天涨跌幅、现价距上方最近一条压力位还差多少
```

**关键分工（沿用 HANDOFF §4）：**

- 算法**唯一职责**是挑出值得看一眼的币 + 算距离；**不做入场判断**
- 压力位**永远由用户标**，算法不猜
- 粗筛**允许很不准**（80% 精度即可），因为它只是筛掉“最近根本没拉过的币”

## Background / 已确认事实

### 上一轮证明了什么、否掉了什么

| 结论 | 出处 |
|---|---|
| 用户的压力位 = **这一波拉升的最高点**（31/31 落在“区间前 30 根最高价”1 个日均波动内） | HANDOFF §2.2 |
| 用户标的是**拉升之后的横盘段**，不是拉升本身（区间内涨幅中位仅 5%） | 本轮 `diag-miss.mjs` |
| 用“锚点 + 判据”自动认横盘/认顶，16 条全失败 | HANDOFF §3 |
| 固定窗口（60/90/120/150）与死阈值（15%、2%、0.5%）禁用 | HANDOFF §5.3 |

### 本轮实测（443 个加密币、200 根 1D，数据到 2026-10-20）

**粗筛 v1（“现在正在拉升里”）：** 覆盖 18/38，但**35% 的币日都命中**，等于什么都报 → 否决。

**粗筛 v2（“拉升 → 横住”，多参数扫描）：** 覆盖 24/38（63%），但**与同币随机日完全不可分（1.0×）**。原因：池子本身是“最近涨过的热门币”，90 天里几乎都有一段拉升 → 单靠“拉过没有”无法区分。**因此粗筛的目标不设成“复现用户的段”**，而是“挑出值得看一眼的币”。

**当前粗筛（v3）：** 拉升 ≥30% 且 ≥4 天、顶之后回吐 ≤60% → **85 个币**（全池 443）。口径纯相对量，无绝对百分比阈值。

**第 3 步的口径已验证：**

| 量（38 段里 31 段有水平线） | 中位 |
|---|---|
| 现价 vs 用户画的那条线 | 8.11% |
| 现价 vs 区间内已见最高价 | 9.02% |
| 现价 vs 上方最近一条用户线 | 8.11%（与 A 一致） |

⇒ “距上方最近一条线”与“距用户自己标的那条”几乎等价，**这个数字算法不需要猜任何东西**。

## Requirements

### R1 · 粗筛只做一件事

- **R1.1** 粗筛输出 = 「币 + 拉升区间（起始日 → 顶）+ 这波涨幅」。不含压力位、不含收敛、不含买卖建议。
- **R1.2** 判据全部相对该币自身（涨幅、回吐比例），**禁止**绝对百分比死阈值。
- **R1.3** 粗筛规模要克制：当前口径下全市场 ≤100 个币；口径变化必须重新报规模。
- **R1.4** 粗筛**不追求**复现用户 38 段（已实测不可分）；它的验收只看“漏不漏掉明显在拉升的币”。

### R2 · 压力位由用户标

- **R2.1** 用户在第 1 步给出的区间图上标水平线；线存下来，跨天复用。
- **R2.2** 同一币可有多条线；可删、可改。
- **R2.3** 算法永远不自动生成压力位。

### R3 · 每天只报两个数

- **R3.1** 当天涨跌幅 =（今日收盘 − 昨收）/ 昨收。
- **R3.2** 距压力位 =（**上方最近一条用户线** − 现价）/ 现价。没有上方线时显示“已破线”而不是负数。
- **R3.3** 不输出任何“该不该做”的结论、不打分、不排序成推荐。
- **R3.4** 数字照实报，不做门槛（不出现“≤2% 才算贴近”这类判据）。

### R4 · 硬约束

- **R4.1** 数据口径不变：北京 8:00 日线（= UTC 00:00），`dayOf = new Date(t).toISOString().slice(0,10)`；股票/RWA 用 Bitget `isRwa` 剔除。
- **R4.2** 不复活 `detectConvergence`、不新增形态检测。
- **R4.3** 不改现有扫描池与粗筛的既有实现（本任务只在研究层验证，产品化另议）。

## Acceptance Criteria

- [ ] **AC1** 粗筛脚本可复跑：给定当日数据，输出币 + 拉升区间 + 涨幅，规模 ≤100。
- [ ] **AC2** 粗筛不出现任何绝对百分比阈值（代码里只有相对量与本币自身参照）。
- [ ] **AC3** 用 38 段标注回放：每个有水平线的币日都能算出「当天涨跌幅 + 距上方最近一条线 %」，无 NaN。
- [ ] **AC4** 距压力位口径自检：现价低于所有线时“已破线”，现价在多条线中间时报**上方最近**那条。
- [ ] **AC5** 口径交叉验证：现价 vs 用户那条线、vs 已见最高价的中位差 ≤2 个百分点（本轮实测 8.11% vs 9.02%）。
- [ ] **AC6** 不复现上一轮的失败做法：无固定窗口、无绝对阈值、无形态判据、无自动顶。

## Out of Scope

- 自动找顶 / 自动找压力位（HANDOFF §5.3 明令禁止）
- 「弹回来并收敛」的判定（上一轮优先级 2，用户本次没有要求，先不做）
- 任何“能不能做”的判断与排序
- 产品界面（本任务只交付研究层脚本 + 口径验证，UI 另开任务）

## Key Decisions

1. **粗筛不承担“认横盘”的职责**。实测 v2 与随机不可分，继续在粗筛里加判据就是重走 16 条失败路。
2. **粗筛规模以“用户愿意看”为准**（≤100），而不是以完整度为荣。
3. **距离口径取“上方最近一条”**（用户 10/20 选定），且与“距用户那条线”实测几乎等价，风险低。
4. **不做任何结论输出**，只报数字——这是用户明确要求的形态，也是上一轮反复翻车的修复。
