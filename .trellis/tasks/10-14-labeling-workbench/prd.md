# 收敛标注工作台：候选抽样 + 标注页生成

## Goal

把现有 17 个 1D 标签扩到几百个，先交付**能重复运行的工具**：脚本按三类采样框抽候选 → 生成可键盘快标的独立静态页 → 用户标完导出 `labels.csv`。本任务只交付**工具 + 口径模板**，不交付用户实际标出来的那批标签。

## 触发 / 背景

- 现有 1D 标签只有 12 个（正 2 / 负 10，见 `research/labeling-sheet-1d.md`），而且**恰好等于检测器的合格名单**——用户从未对"检测器拒绝的那批"表过态，所以无法评估漏检。
- 当前 1D 口径下可标样本上限 ≈ 45（全池合格数，`labeling-sheet-1d.md` 附录 A）。**不换采样框，标签数量直接封顶在几十**，到不了几百。
- 单张标注成本是瓶颈，且标签会随行情腐化（既有标定只稳 8 天）。需要把"每张 10 秒"做出来，并把标签绑定到 `(币, 周期, 快照锚点)` 上，使其可复现、可重标。

## 范围

- 采样周期：**仅 1D**。
- 数据源 / scope：Bitget（现有默认源）× crypto scope。
- **不含**：AI 预标注、4H 及以下级别、任何生产 UI（`src/ui`）改动、训练分类器。

## Requirements

### R1 候选抽样（三类框）

- **R1.1 快照冻结**：一次运行固定一个 `anchor`，抓到的 1D K 线按 `(币, 周期)` 落地为缓存文件；后续重跑抽样必须复用同一缓存，结果逐行一致。
- **R1.2 池定义与线上一致**：沿用 `CoinScanService` 的现有口径——24h 成交额下限（Bitget crypto `100_000`）、`isScannable`、crypto scope。不得新增筛选门。
- **R1.3 三类来源与配比**（可配置，默认如下）：

  | 类别 | 定义 | 默认数量 |
  | --- | --- | --- |
  | 合格 | 通过 1D 粗筛（`coarseScreen`） | 全量（10/14 实测 152） |
  | 边界 | **未**通过粗筛，且 `score ∈ [bandMin, bandMax]`（默认 `[0.35, 1]`） | 全部，**不按数量截断**（10/14 实测 49） |
  | 拒绝 | 其余，随机抽（固定随机种子） | 30 |

  > 边界**不能**写成"按 score 降序取前 N"：10/14 首跑发现 31 只检测器判"1D 收敛"的币里有 **21 只没通过粗筛**，且它们的 score 最高，会被前 N 截断整组吃掉——而"检测器说收敛、粗筛说不要"正是信息量最大的一格。**分数窗口是唯一的口径旋钮**，`--band-max` 用来收窄到贴着门槛的那一段。

- **R1.4 每条候选记录特征**：`instrument / anchor / coarse 三量(rangePct,netPct,posRange) / 本扫描的池内阈值 / score / qualified / 24h 成交额与排名`，供标注页展示与后续分析。
- **R1.5 输出**：`out/candidates.json` + `out/candidates.csv`。

### R2 标注页

- **R2.1 独立静态页**：单个 HTML 文件 + 本地拷贝的图表库，**断网可打开可用**；不依赖 dev server、不改 `src/ui`。
- **R2.2 交互**：一次显示一张较大的 1D 图，键盘 `Y`=好 / `N`=不好 / `?`=拿不准，自动翻页；支持上一张回退。
- **R2.3 理由标签**：可选，每个标签可附一个理由。默认集按**判据本身**给：`前期波幅不够 / 振幅没缩小 / 上沿斜 / 位置太高 / 就是好`（+ 自由文本）。
  > 用户 10/14 明确否掉了"时间太短"这类理由：**时长是充分不必要条件**——久不久既不保证好、也不因短淘汰。真正判的是**结构饱满不饱满**：前期波幅够不够大 + 振幅有没有逐步缩小。理由集必须跟这条对齐，理由表写在 `label-rubric.md`。
- **R2.4 防带偏**：默认**不显示**检测器 `score`，可用一个开关打开；开关状态记入导出，供日后区分盲标/非盲标。
- **R2.5 断点续标**：进度存 `localStorage`，关页面重开继续；可一键导出 `labels.csv`。
- **R2.6 导出字段**：`instrument, timeframe(1D), anchor, label(Y/N/?), reason, scoreShown(0/1), labeledAt`。

### R3 口径模板

- 一份 `label-rubric.md` 骨架：三句判定口径（**按"结构饱满度"写，明确排除"时长"**）+ 教具卡位（3 好 / 3 差 / 2 边界）+ 理由标签表。**内容由用户填**，工具只提供结构与示例格式。

### R4 可复现与可回归

- 同一快照 + 同一配置重跑 → `candidates.csv` 逐行一致。
- 工具是**纯新增**：不动 `src/`、不动生产 UI；现有 `npm test` 全绿。

## Acceptance Criteria

- [x] AC1 抽样可复现：同一缓存跑两次 `candidates.csv` 完全相同；换随机种子只影响"拒绝堆"那一类。（连续 3 次 md5 相同）
- [x] AC2 三类来源齐全，数量符合配置；合格类数量等于该快照粗筛实际通过数。（152 / 49 / 30）
- [x] AC3 断网后直接打开生成的 HTML 仍能出图、能标、能导出。（页面零外部引用，只挂同目录本地图表库）
- [x] AC4 键盘 `Y/N/?`、回退、导出 `labels.csv` 均正常，导出字段符合 R2.6。（jsdom 行为断言 23 项全绿）
- [x] AC5 断点续标：标 N 张后关页面重开，已标进度不丢、未标从断点继续。（index 一并持久化，重开回到断点）
- [x] AC6 `label-rubric.md` 存在且含三句判定 + 理由表骨架。
- [x] AC7 `npx tsc --noEmit` 通过（`tools/` 纳入检查）；`npm test` 全绿（67 文件 / 524 测试）。
- [x] AC8 工具不改动 `src/` 与 `src/ui`：`git status` 中 `src/` 无改动。

## Out of scope（后续独立任务）

- AI 预标注链路（人盲判 → AI 草稿 → 纠偏）与一致率度量。
- 4H、以及 5m/15m/1H 的标注。
- 用积累的标签重标定阈值或训练分类器。
- 多轮快照批量调度（本轮跑一轮；换日期再跑属操作，不属工具）。

## Notes

- 采样比例（R1.3）与"合格类是否含 `posRange` 被 floor 砍掉的币"都要用户拍板；默认值按本 PRD，落地后可在运行参数上调整。
- 本任务不产出标签结论；AC 全部关于"工具能跑出可用的标注输入并能收集回标签"。
