# 收敛扫描：用「价格停在自己近期走势的位置」替掉「后面比前面安静」

> 状态：planning → **待激活**（用户 10/19 晚已拍板三个开放问题；研究已复核，结论见 `research/findings.md` §4.5）。
> 完整研究过程与全部数字：`research/findings.md`（12 个原脚本 + 10 个复核/对照脚本在 `research/scripts/`）。
> 目录名 `fakeout-retest-quality` 是讨论中途的工作名，实际范围已从“假突破回踩”改为“替换收敛判据”。

## Goal

**扫描器要回答的唯一问题：现在能不能做。**

把扫描判据从「最近一段比等长前一段安静」换成 **「价格保住了最近这波上涨的几成」**（`retention`），每天按**全市场排名**取前 **10%** 作为候选。画线提醒作为标注工具的一部分，不进扫描判据。

> **判据 vs 回测的定位（用户 10/19 晚定调）**：
> - **产品** = 「现在能不能做」。列表就是此刻满足条件的币，刷新一次看一次。
> - **回测** = 「这几个月里哪几段是能做的」，**只用来验证扫描机制可不可行**，不是产品形态。
>   回测通过 ≠ 上线即准；回测不通过 = 机制不成立，必须换。
> - 因此所有离线验证（用户标注区间、收敛后突破率、区间回放）都属于**回测**，结论只能用来决定“这个机制要不要上”，不能当作线上效果承诺。

用户 2026-10-19 原话（决策来源）：

> 我也觉得“后面这段是不是比前面安静”这种做法不对……想想怎么替代掉

> 支持“价格停在自己近期走势的哪个位置”这个说法

> 我们不用形态了，之前的尝试证明了形态的准确率很低，绝对宽度也不行，换个币种可能就失效了，那还是用 2 吧（位置对就够了）

> 最终要回答的是现在能不能做，"这几个月里哪几段是能做的"只是我想确认我们这个扫描机制可不可行，也是一种回测

## Background / 已确认事实

### 现有判据无区分力（实测）

- 线上 `detectConvergence` 的 `score`（`src/domain/coin-scan.ts:663`）在 282 条可用人工标签上：**前 10% 精准率 7.1%，低于 12.8% 的随机基线**。
- CFX（10-19 实时）：冲高 55% 后阴跌回吐，`detectConvergence` 判合格 `score = 0.716`、`detectBoxBrace` 也判合格——两者都只测“变安静”，不看“停在哪”。
- 全市场每天约 **244** 个信号（10-18 实测），列表排序按 `bestScore`（即上述反向的 score）。

### 已证伪的四条路线（详见 findings §2）

1. **回踩质量**（回踩位置 + 阴跌动量）：用户否决（太复杂），且 WAL 是真突破而非假突破样本；
2. **按行情分段**：三种认行情方式都试过，CFX 在任何一种下都能混过去，分段替代不了判据；
3. **绝对收敛**（最近 N 天区间够窄）：33 段用户标注的好区间只覆盖 8/33（20 天≤25%），且 Y 里有 26%~60% 宽的段；
4. **收缩度量 / “第一次回到顶部”事件**：收缩度前 10% 精准率 7.1%；事件化把 WAL/BEAM/AXL/TIA/OPG/STRK 全误杀。

### 推荐判据（已实测 + 10/19 晚复核）

```
窗口 = 最近 60 根日线
lo   = 窗口内最低收盘（不是最低最低价：影线会给它送假谷，见 findings §4.5 E）
hi   = lo 之后窗口内最高价
retention = (lastClose - lo) / (hi - lo)     // 1 = 还贴在顶上，0 = 跌回起点
offHigh%  = (1 - lastClose / hi) * 100
候选     = 当天全市场 retention 排名前 10%
```

| 证据 | 结果 | 出处 |
|---|---|---|
| 单币 | WAL 0.87 / CFX **0.07** | findings §3 |
| 用户标注 15 段回放（top10%） | 覆盖 **9/15** | findings §4.5 C |
| 窗口长度 | W=60 在 5 个锚点上最好且最稳 | findings §4.5 D |
| **因果验证（主证据）**：贴顶收敛（5 根区间≤5%）后 5 日收盘突破 | retention 80-100% 档 **52.2%** vs 0-20% 档 **27.1%**；无条件 **38.9%** | findings §4.5 K |
| 叠加更严的形态门 | 不改善（只砍量） | findings §4.5 F |
| 卡片图（16 张，含 WAL/CFX 与用户 15 段标注） | `research/retention-cards.html` | findings §4.5 J |

> ⚠️ 两个**不能用**的数字：
> 1. 旧结论的“前 10% 精准率 40%”——分母取错（带内标过名 6/15 而不是带宽 6/68），按带宽只有 8.8%，**低于 12.6% 基线**；
> 2. “之后 5 天守住率 64.7%”——**WAL 本身就没守住却判 Y**（findings §4.5 J），“守住”不等于“好机会”。
> 验收只用第 4 行那个（收敛后突破率，见 AC3）。

### 已知缺陷（用户提问后核实，见 findings §4）

1. **它是“强势币筛选器”**：36 个 Y 里 30 个最近 60 天涨幅 > 60%；涨幅 ≤40% 的只有 2 个。这不是缺陷，是用户的实际偏好——反过来筛“刚拉的币”会干掉 34/36 个 Y。
2. 牛市候选多、熊市候选少（排名是相对的）。
3. 分不清“高位横着等突破”和“高位做头”——交给人工判读。
4. **人工画线对提升选品精度证据不足**：用户想要的“底部拉起→箱体上沿→收敛”在这批 Y 里几乎不存在（只有 GWEI 接近）。画线定位改为**标注/交易计划工具**。

## Requirements

### R1 · 扫描判据（排序与入选）

- **R1.1** 判据 = `retention`（定义见上）+ **当天全市场排名前 X%**；X 由界面参数给出，默认 **10%**。
- **R1.2** 排名是相对量：不写死任何绝对阈值；窗口取 **60 根**（已定，做成常量并可参数覆盖）。
- **R1.3** 输出到列表：`retention`（0~1，显示成百分比）、`offHigh`（离这波高点还有多少 %）、以及一句可读理由（例：“保住 87%，离高点 3.1%”）。
- **R1.4** 排序键改为 `retention` 降序（同分保持原有 ticker 顺序）；不在前 X% 的币**不出现**在列表里。
- **R1.5** 删掉 `bestScore` / 「强度分」列（用户决定）；`StructureResult.score` 字段本身保留（10/12 契约），只是不再上行到 `ScanRow`、不再显示。

### R5 · 用户 10/19 晚逐只看图后新增的硬约束（必须进判据或明确记为不满足）

用户在 `research/raw-look.html` / `scanner-vs-marked.html` 上逐只判读，提出的不是偏好而是规则：

| # | 用户原话 | 落成什么 |
|---|---|---|
| R5.1 | 「NEAR 不对，他那个底部盘整我是不会去看的，**拉起来后收敛才会看**」 | 候选必须满足：**横盘之前 20 根里有 ≥20% 的上涨**。全池 3 根横盘里有 **55% 是盘底/下跌途中**的，这条直接砍掉一半噪音。 |
| R5.2 | 「**区间 3 根是可以的**，日线级别还是比较大」 | 横盘最短长度 = **3 根日线**，不能用现有的「band 至少 5 根」。 |
| R5.3 | 「OP 扫到的 09-26→10-10 **波动太大**；应该扫到的是 10-10~10-12 那几根**加前面的收敛三角**」 | 报出来的区间**自身必须是平的**：段内最高/最低的来回幅度 ≤ 段的明确上限（现在 detectConvergence 只要求"比前一段安静"，不要求带本身平）。 |
| R5.4 | 「**ZEC 没扫到是不应该的**」（05-20→08-17 大三角） | 长箱体（20~90 根）必须能报出来。 |

| R5.6 | 「你自己的名词太复杂了看不懂」 | 列表/页面文案用日期和价格说话，不引入自造术语（如"区间末位置""收敛框"）。 |

> **R5 与 R1 的关系**：R1（retention 排名）回答"现在位置好不好"；R5 回答"这一段算不算横盘、值不值得看"。两者**都要**——只做 R1 会把 NEAR 那种底部盘整和 OP 那种来回 40% 的带照样报出来。

### R2 · 已有收敛/箱体结果的处置

- **R2.1（10/19 晚更新，用户决定）** `detectConvergence`（"看变安静"）**删掉**：经过多轮修改和讨论，这个量本身不好用，不再作为任何周期的判定或报告列。
  - 删除范围：`probeStructure` 不再调用它；列表的「收敛结构」列与明细子表里各周期的那一列一起下线；`minScore`（结构强度阈值）随之**没有作用对象**。
  - 保留范围：`StructureResult` **类型**与 `detectBoxBrace` 不动（箱体蓄力是独立方法，用户没否它）。
  - 删除理由与证据：`score` 在 282 条人工标签上前 10% 精准率 7.1%（低于 12.8% 基线）、排序方向反的；CFX 冲高回吐照样合格；OP 段内来回 40% 照样合格（findings §1 / §4.5 / §O）。
- **R2.2** 行是否出现，由 `粗筛（不变） ∧ R1 排名前 X% ∧ R5 形态约束` 共同决定。
- **R2.3** `minScore` 输入框与 `TIMEFRAME_SCORE_OFFSET` 一并下线（它只服务于已删除的 `score`）；界面不再显示「结构强度阈值」。

### R3 · 扫描 + 人工标注结合（用户 10/19 晚提出）

用户原话：

> 我们最终可以扫描和人工标注结合，就是先扫出来然后我可以去标注箱体的线或者三角的线，再去判断说这个币是不是在这些关键点位附近收敛

流程：

1. **扫描器先扫**出候选（R1 + R5），并给出它识别到的箱体/三角上下沿候选线（作为**初始建议**，用户可改）。
2. **用户画线**：在图上把箱体上沿/下沿、或三角的两条斜边画出来（已有的水平线/射线，需补**斜线**）。
3. **系统判断"是不是在这些关键点位附近收敛"**：用用户画的线去量——最近这段价格是否贴着这些线运行、是否还在两条线之间、离线还有多远。
4. **结论回写到列表**：例如「在你画的上沿下方 1.2%，已贴着横 6 根」。

约束：

- **R3.1** 画线是**用户的可信输入**，高于扫描器的自动识别：两者冲突时以用户画的为准。
- **R3.2** 扫描器识别出的线只是**初始建议**，用户没有画线时用它兜底（并标明"自动识别"）。
- **R3.3** 画线需要支持**斜线**（三角的边是斜的，现在只有水平线/射线不够）。
- **R3.4** 画线和判定结果都留在该品种上，下次打开还在。

### R4 · 硬约束

- `detectBoxBrace`（箱体蓄力方法）与 `StructureResult` 类型契约不变；不复活旧的三角/摆动**自动检测**模块（10/12 决策）——三角只在**用户画线**里出现（R3）。
- 不改粗筛（池内分位 + `posRange ≥ 0.03`）与扫描池。
- 1D 序列长度沿用 `SCAN_WINDOW = 100`（≥60 根即可算 retention，**不新增取数**）。

## Key Decisions

1. **判据换成位置**。验收正据改用 **收敛后突破率**（用户自己定义的"好机会"：贴顶收敛 → 5 日内收盘突破）：retention 80-100% 档 **52.2%** vs 0-20% 档 **27.1%**，无条件 38.9%（findings §4.5 K）。**不是**旧研究里的"精准率 40%"（分母错），也**不能**用"5 日守住率"（WAL 被判 Y 却没守住，findings §4.5 J）。
2. **不写死任何绝对阈值**，用“当天全市场前 X%”代替；X 默认 10%。
3. **不用自动形态、不用绝对宽度、不用分段**做判据——四条路线均已实测证伪；也**不叠加**更严的自动形态门（findings §4.5 F：只砍量不提纯）。
4. **WAL 是真突破 + 主升浪走完后的高位收敛**；CFX 是冲高后阴跌回吐（两者 retention 0.87 vs 0.07）。
5. **"看变安静"（`detectConvergence` / `score`）删除**（用户 10/19 晚决定，见 R2.1）。
6. **“第一次回到顶部”事件化被否决**（会误杀持续在高位的好结构）。
7. **窗口 60 根、起点取最低收盘**（findings §4.5 D/E）。
8. **旧 `score` 列删除**（用户 10/19 晚决定）。
9. **预期口径要诚实**：位置是**弱的单调分量**（把"收敛后突破率"从 39% 提到 52%），主要价值是把每天 244 个信号收到约 60 个；它不是"筛出必然做对的币"。
10. **产品只回答"现在能不能做"**；「哪几段能做」属于回测，只用来判断机制是否成立（用户 10/19 晚定调）。
11. **判据 = 位置（R1）+ 形态约束（R5）两条腿**：R1 解决"是不是还在高位"，R5 解决"这段算不算横盘 / 是不是拉起后的"。单用任一条都被用户当场否掉过（NEAR=只有位置没有拉起条件、OP=只有"变安静"没有"本身平"）。
12. **最终形态是"扫描 + 人工画线"结合**：扫描器负责扫出候选并给初始边界，用户画箱体/三角的线，系统判断价格是否贴着这些线收敛（R3）。自动识别**永远只是建议**，用户画的线才是准绳。

## 删掉"看变安静"会连带改什么（10/19 晚核实，供实现时对照）

用户决定 R2.1 删掉 `detectConvergence`。这个函数是**整条扫描行的判定链**，删它比删一列影响大，先把会碎的地方列清楚：

| 位置 | 现在 | 删掉之后 |
|---|---|---|
| `probeStructure` / `cashScanned` 的第二阶段 | 为粗筛通过者取 5m/15m/1H/4H，逐周期算 `detectConvergence`，**只有 5 档全合格才出行** | 这 4 个周期的取数**整个不需要**；第二阶段可以下线 → 扫描从「每币 1 + 通过者 4 次取数」降到「每币 1 次」 |
| `ScanRow.convergedTimeframes` / `qualifiedCount` / `bestScore` | 行契约的核心字段 | 全部删除（行 = 粗筛通过 ∧ R1 排名 ∧ R5 形态约束） |
| 排序 | 最高合格周期 → 合格周期数 → `bestScore` | 只剩 `retention` 降序 |
| 界面 | 「收敛结构」列 + 明细子表（各周期结构/位置/强度分/触碰） | 整列与子表下线；列表改成 R1/R5 的字段 |
| `minScore` 输入框 | 结构强度阈值 | 无作用对象，下线 |
| 既有测试 | `coin-scan-service.test.ts` 里大量用例围绕"5 档全合格才出行"（例如「只合格 5m 的币要出行」「sink a survivor…」） | **这些用例的前提消失，必须重写**，不是改一个断言 |
| `detectBoxBrace` | 独立的「箱体蓄力」扫描方法 | **不动**（用户没否它），它和 `detectConvergence` 本来就没共用代码 |

> 这条影响了原 PRD 里「保留形态检测 / 只换排序层」的定位：现在是**删掉形态层、扫描直接变轻**，收益是取数量降约 80%，代价是测试与界面要重写。
