# 标签支持重命名与删除（全局生效）

## Goal

复盘标签（Review Tag）可以改名字、可以删除，改动**全局生效**：一个标签改/删，所有带这个标签的复盘记录同步更新，而不是只影响当前正在看的那笔交易。入口在复盘编辑器的标签下拉里内联操作，不新增独立的标签管理弹窗。

## Background

- 标签是纯字符串，存在每条复盘的 `trade_reviews.tags_json`（JSON 数组）里，**没有独立的标签表**。全局标签列表 = 扫所有复盘去重排序（`app-plugin.ts:65`）。
- 因此「改名」本质是**把 N 条复盘里的这个字符串替换掉**。只改当前这一笔会让同一个标签分裂成新旧两个，筛选器和下拉里会同时出现两个名字。
- 目前没有删除标签的入口：手滑建了个错名字的标签，只能逐个交易去点掉。
- 入口放在单笔交易的编辑器里，但操作是全局的 —— 所以必须显示「影响 N 笔复盘」，避免用户误以为只改当前这笔。

## Confirmed Decisions

1. **入口**：在复盘编辑器的标签下拉（`TagsCombobox`）里内联操作，每行（已有标签）右侧提供重命名（铅笔）与删除（垃圾桶）图标。不做独立的标签管理弹窗。
2. **顺带做删除**：下拉里可直接删除标签（带影响笔数确认）。
3. **存储模型不变**：继续用 `tags_json` 字符串数组，不引入 `tags` 表 / 关联表 / 数据迁移。理由：本地单用户工具，复盘几百笔，全量替换成本可忽略；引入标签表的收益（O(1) 改名、标签元数据如颜色/排序）本次不需要。
4. **重命名到已存在的名字 = 合并**：把旧名字的所有引用指向新名字；同一条复盘若新旧都有，去重后只保留新名字。提示语明确写「将合并到已有标签」。
5. **显示使用笔数**：下拉里每个标签显示它被多少笔复盘使用（用于确认影响范围）。
6. **操作后前端全量打补丁**：更新全局 `tags` / `tagCounts`、所有 `trade.review.tags`、当前筛选值 `filters.tag`、以及编辑器里未保存的草稿标签——不重新拉取 `/api/trades`。
7. **只读场景不变**：筛选下拉（`<select>`）里的标签列表同步更新，但不提供改名/删除入口。

## Requirements

### R1. 存储层（`ReviewStore`）

- `renameTag(from: string, to: string): number`：事务内把全部复盘中等于 `from` 的标签替换为 `to`，去重去空，写回；返回受影响的复盘笔数。
  - `to` 去空格后为空 → 不改动，抛错/返回 0（由 API 层返回 400）。
  - `from` 不存在 → 返回 0。
  - `to` 已存在 → 合并（每条形变后去重，只保留 `to`）。
- `deleteTag(tag: string): number`：事务内从全部复盘中移除该标签，返回受影响的复盘笔数；标签不存在 → 返回 0。
- 两个操作都要在一个事务里完成，中途失败不留半成品。

### R2. API

- `GET /api/trades` 响应新增 `tagCounts: Record<string, number>`（每个标签的使用笔数），`tags: string[]` 保持原样不动（向后兼容）。
- `POST /api/tags/rename`，body `{ from, to }` → `{ affected, tags, tagCounts }`（后两者为操作后的全局最新值）。`from`/`to` 缺失或 `to` 空 → 400。
- `POST /api/tags/delete`，body `{ tag }` → `{ affected, tags, tagCounts }`。`tag` 缺失 → 400。
- 非 POST → 405（与现有 `/api/reviews` 一致）。

### R3. 前端交互（`TagsCombobox` / `ReviewEditor` / `App`）

- 下拉中每个**未选中**的已有标签行：显示 `名称 · N 笔`，hover 时右侧出现铅笔（重命名）与垃圾桶（删除）。
- 点铅笔 → 该行变成输入框（预填当前名、全选），Enter 或 ✓ 保存，Esc 或 ✗ 取消；空输入不可保存。
- 点垃圾桶 → 该行变成行内确认：`删除「X」？影响 N 笔` + 确认/取消。不使用浏览器原生 `confirm`。
- 重命名到已存在的名字时，确认文案改为「将合并到已有标签「Y」，影响 N 笔」——但仍是行内输入即保存，不额外弹确认框（笔数已显示在行上）。
- 重命名/删除进行中该行禁用，失败时在该行显示错误提示（网络错误 → 提示并可重试），不静默失败。
- 操作成功后：`App` 用返回的 `tags`/`tagCounts` 打补丁，并同步所有 `trade.review.tags`、`filters.tag`、以及编辑器草稿里的同名标签。
- 已选中的标签（chip）行为不变：点击仍是「移除出当前这笔」，不是全局删除。

### R4. 草稿一致性

- 重命名/删除后，当前编辑器里未保存的草稿标签必须同步变化（旧名 → 新名；删除 → 从草稿移除），否则用户一保存又把旧名字写回去。
- 实现方式：操作成功后由 `App` 通过给 `ReviewEditor` 的 `key` 加版本号强制重建草稿（现有 `useEffect` 只依赖 `trade.id`，不会因外部标签变化而重建）。

### R5. 术语

- `CONTEXT.md` 的 **Review Tag** 条目补充：标签名是全局共享的，改名/删除会影响所有带该标签的 Trade；新增 **Tag Rename / Tag Delete** 相关描述与一条 Example Dialogue。

## Acceptance Criteria

1. 标签「箱体突破后找拐点」用在 5 笔复盘上，在任意一笔的下拉里改名为「假突破」→ 5 笔全部变成「假突破」，筛选下拉和标签下拉里不再出现旧名字。
2. 改名为已存在的标签「止损太晚」→ 旧标签的引用合并过去；原本同时带这两个标签的复盘只保留一个「止损太晚」。
3. 删除标签 → 所有复盘上该标签消失，其余标签不受影响，返回的影响笔数正确。
4. 下拉里每个标签显示的笔数与实际一致。
5. 改名/删除后，正在编辑的草稿里的旧标签名同步更新（保存后不会写回旧名）。
6. 若当前 `filters.tag` 正好是被改名的标签 → 筛选值跟着改成新名字，队列不清空；被删除的标签 → 筛选值清空（回到全部）。
7. `renameTag` / `deleteTag` 中途出错时数据库不留半成品（事务）。
8. `npx vitest run` 全绿；`npx tsc --noEmit` 无新增错误。
