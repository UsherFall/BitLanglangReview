## 0. 结论

**推荐交付:1D 收紧版(7/7)。**

理由一句话:**4H 在同一日历跨度上的结构量与 1D 逐值相等,不产生任何新信息;而它的 4 小时节奏让同一份常量要在 6 倍多的时刻上成立,稳定性反而更差。**

但必须同时说清楚:**两套都不能满足"一份写死的常量长期不越 50%"这个强要求**。1D 收紧版的最好成绩是 **8 天不越线**(第 9 天 51.6%)。所以真正要用户拍板的是:

> **是否接受「粗筛参数需要定期(≈1~2 周)重标」?**
> - 接受 ⇒ 交付 1D 收紧版,7/8 覆盖,池率均值 **36%**,`worst ≤ 50%` 的窗口 **8 天**。
> - 不接受 ⇒ **两套都不能交付**;必须承认"1D 单靠 `rangePct/netPct` 两个标量做粗筛"这条路线到此为止,应转向第 2 段(小级别绝对收敛)承担全部精度。

## 2. 三件必须纠正的既有假设

| 既有说法 | 实测 | 影响 |
|---|---|---|
| "4H 正常 200 根 ≈ 33 天" | **540 根 = 90 天**(`limit=1000`;`limit≥1001` 报错) | 上一轮"4H 数据更宽裕"的设想前提不成立 |
| "4H 200 根 ≈ 33 天,比 1D 的 89 根更宽裕" | 1D **89 根 ≈ 89 天**(API 上限 90 根)vs 4H **540 根 = 90 天** —— **日历跨度相同** | 4H 在"盘得够久"这个维度上**没有优势** |
| "4H 分辨率高 4 倍,可能让 ACE 离阈值更远" | **ACE 的区间在 4H 与 1D 上逐值相等**(33 天窗口两边都是 51.518%) | 假设被数据否定;ACE 依旧单独顶住 `W` |

## 3. 4H 唯一真实的增量,以及它的代价

4H 允许 `T` 取 **非 6 的倍数**(日内 4h 粒度)。X = 33 天时:

| | 1D | 4H |
|---|---|---|
| 可选 `T` | 33 天(整日) | …T=190(31.67 天)、T=191、… T=198(33.0 天)… |
| 最优 `W` 下限 | 51.52% | **48.85%**(取 T=190) |
| 表面收益 | — | **−2.66pp** |
| 真实代价 | — | 窗口**短了 1.33 天**(不是同一个"盘整时长");且"正好躲开那根极值 bar"= 刀锋选点 |

在 X = 30/35/45 天时,这个细粒度的改善是 **0.00pp**(无处可躲)。⇒ **不构成可交付的稳健性。**

## 4. 推荐

### 4.1 推荐:1D 收紧版(7/7)

**交付参数(按"维持 1 周"口径,`d ∈ {0..7}` 全部成立):**

```
structureLen T = 23 天
rangePct    W = 0.47762763656566876   (47.7628%)
netPct      D = 0.10900243309002428   (10.9002%)
```

| 预期 | 值 |
|---|---|
| 正样本覆盖 | 7/8(PROM ✔ / RIVER ✔ / KAVA ✔ / CATI ✔ / BLESS ✔ / BGB ✔ / TRX ✔ / **ACE ✘**) |
| 负样本 | 0/9 混入(每一个锚点都成立,本轮最稳的一侧) |
| 池通过率(d=0 最差日) | **224/465 = 48.2%** |
| 池通过率(8 天均值) | **168.5/465 = 36.2%** |
| 有效期 | `≤50%` 维持 **8 天**;第 9 天 51.6%;完全可行上限 11 天 |

**若愿意接受更短的重标周期**(frontier,`coarse-1d-tight-anchor.csv`):

| 重标周期 | 最优 `(T / W / D)` | 最差池率 | 平均池率 |
|---|---|---|---|
| 每天 | 25 天 / 45.909% / 4.248% | **11.8%** | 11.8% |
| 每 2 天 | 25 天 / 46.140% / 5.009% | 14.0% | 11.9% |
| 每 4 天 | 28 天 / 47.622% / 9.202% | 36.6% | 32.7% |
| 每 5 天 | 29 天 / 47.622% / 10.956% | 40.0% | 36.0% |
| 每 6 天 | 26 天 / 47.763% / 11.370% | 45.2% | 33.8% |
| **每 8 天** | **23 天 / 47.763% / 10.900%** | **48.2%** | **36.2%** |

### 4.2 ACE 的归属

ACE 在 1D 收紧版下是**结构性失配**,不是刀锋:

- `T=25 / 45.909% / 4.248%`:区间 **48.9% vs 45.909%(+2.9pp)**、净漂移 **21.9% vs 4.248%(+17.6pp)**,双维度越界;
- **d=0..15 共 16 个锚点,ACE 一次都没通过**;
- `T=23 / 47.763% / 10.900%`(8 天口径):ACE 区间退到 46.0%(**能过区间门**),但净漂移 **21.6% vs 10.900%(+10.7pp)** 仍被稳稳拦住。

⇒ **交给第 2 段(小级别绝对收敛,R2)承担是安全的**:它在 1D 这一层既不能被"区间上限"容纳,也不能被"净漂移上限"容纳,而这两条恰好是第 1 段的全部手段。

### 4.3 为什么不用 4H

| 论点 | 数据 |
|---|---|
| 4H 没有新信息 | 日对齐窗口上与 1D **逐值相等**(§1.2),16/16 个取样点 Δ = 0.0pp |
| 4H 没有把 ACE 拉开 | `W` 下限 33 天窗口两边都是 **51.518%**,由 ACE 单独顶住;ACE 领先 7 正 5.6pp 两边相同 |
| 4H 的真实节奏更差 | 7/7 `≤50%` 从 1D 的 **8 天** 降到 **4 天**;8/8 从 **2 天** 降到 **1 天** |
| 4H 的成本更高 | 6 倍的 bar(540 vs 89)、6 倍的取数量、6 倍的评估时刻 |
| 4H 的唯一增量 | 日内 `T` 粒度 → 收益 0.00~2.66pp,且必须用"缩短窗口"换来(§3) |

### 4.4 什么情况下我才会建议 4H

只有当**第 2 段(小级别绝对收敛)也选择 4H**、并且希望**第 1、2 段用同一时间框架**以减少数据管道的时候。从"粗筛质量"这个单一目标看,4H **没有任何可取之处**。

## 7. Caveats

- **1D 收紧版的锚点回移是"同一份 89 根缓存往回切窗口"**,不是"真拉到历史某天的快照"。上一轮 §5.4 曾用 10-13 现拉快照复核该方法(逐值一致),本轮未重复。
- **CSV 里 `W`/`D` 印到 5 位小数,回填会掉样本**(浮点)。交付请用 §4.1 的全精度值。
- 4H 数据是 10-13 现拉的,通过 `endTime` 对齐到与 1D 末根**同刻结束**;若不做对齐,ACE 区间会系统偏高 +0.5pp(本轮踩过并修正)。
- **未改任何 `src/` / `tests/`,未 commit。**
