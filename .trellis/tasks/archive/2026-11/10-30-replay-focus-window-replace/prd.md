# PRD：回溯复盘点单焦点窗口改为整窗替换

2025-10-30 UsherFall 反馈现场：回溯复盘 BTCUSDT（1H 会话，图表切到 15m）在 **7/17 附近有一段价格「跨越」**。

## 背景与根因（已实证，非猜测）

- 原始 K 线数据本身没问题：7/17 前后 15m/1H 序列连续、无跳空，服务端每个响应都在空洞处截断（`contiguousCandles`），所以**光翻页永远不会画出空洞**。
- 本地缓存有按需回填造成的多段大空洞（当天实测 15m：`6/20 12:45 → 7/3 10:30`、`7/6 13:15 → 7/10 15:00`、`7/21 13:15 → 2026`）。
- **唯一会把两个不相邻窗口拼成同一份渲染数据的路径是 10/29 的焦点取窗**：`loadFocusWindowCandles()` 取一个以开仓点为中心的 `mode=initial` 窗口，然后 `mergeCandles` 进当前游标窗口，**这个合并不做相邻性检查**。
- lightweight-charts 的时间轴按**索引**排列、不为缺失时间留空白，于是相隔近一个月的两个窗口被画成紧挨着 → 价格看起来直接跨越。
  实测（点最后一单 `fill-60`，开仓 6/18 23:30）：`6/20T12:45（close 26839.8）→ 7/18T09:30（open 30003.5）`，**+11.79%**。

## 为什么不能直接搬交割单复盘的模块

两个交割单模块共用 `TradeChart`，它是**「一单 = 一次整窗替换」**的查看器：`trade.id` 变化即清空重挂 → 一次 `mode=initial`（以开仓点为中心）→ `setVisibleRange(entryVisibleRange)`。它没有游标、没有步进、没有会话持久化，所以天生不存在「两个窗口拼一起」。

回溯复盘是**游标式回放**：只揭示到 `cursorTime`、舒适区跟随（10/28）、步进、模拟交易、会话落盘；它的数据窗口锚在**游标**上且必须一直留着（步进与「回到光标」都依赖它）。10/29 把交割单那套单窗口语义贴过来时，为了不丢游标窗口而做成 **merge** —— 缝就从这里来。

结论：可复用的是**语义与窗口函数**（`entryVisibleRange`、以开仓点为中心的一次 `mode=initial`），不是 `TradeChart` 组件本身。修法 = 让「焦点态」在回放图里也走**整窗替换**，游标窗口另存，不拼。

## R1 点单 = 整窗替换（核心）

焦点态（`orderFocus` 存在）下，图表渲染的数据集只包含**该单开仓点周围的窗口**（`entryVisibleRange` 同款 ±150 根），**不再与游标窗口合并**；焦点的锚定语义保持 10/29 不变（视口锚到 `positionOpenTime`，每个 `rangeKey:token` 只定位一次，重复点同一行重新定位）。

验收：

- 点「单子」里的已完成交易行后，图表上**不存在**任何相邻两根之间跨越缓存空洞的时间缝；打开的历史空洞绝不出现在同一份渲染数据里
- 未点单（无焦点）时行为与现在完全一致
- 开仓点不在游标窗口内时，仍只发一次 `mode=initial` 取窗（不逐页追），请求带会话自带 venue（`replayCandleSource`）

## R2 游标上下文不被污染（模拟交易不退化）

焦点窗口数据**不得**喂进 App 的 `freeReplayCandles`：它服务 `currentCursorCandle`（当前价）、浮动盈亏与开平仓可用性。

验收：

- 焦点态下「单子」Tab 切到「操作」Tab，浮盈与「市价开仓/限价开仓/市价平仓」的可用性仍按**游标所在 K 线**计算，不因焦点窗口不含游标 K 线而变成禁用或 `-`
- 焦点态下开平仓提交照旧触发「回到光标」（10/30 契约）

## R3 回到光标 / 切周期（10/29、10/30 契约不破）

- 解除焦点（步进、开平仓、点持仓行、切换/恢复/删除会话、离开回溯复盘）后，视图恢复游标窗口并回到光标，**游标窗口数据必须仍然可用**（不要求用户再手动触发加载、不出现空白图）
- 切周期时焦点跨周期存活（10/29）：新周期下按新周期重新取该单窗口并重新锚定

验收：

- 点单 → 按「下一根」/提交开仓 → 视口回光标，且图上立刻有游标附近的 K 线（不是空窗）
- 点单 → 切 15m → 仍锚在该单开仓点（±150 根 15m 窗口）
- 点单 → 切周期 → 再点「回到光标」（点持仓行）→ 正常回到光标窗口

## R4 焦点态下的平移/翻页

焦点态下平移应从**焦点窗口**继续按既有 earlier/later 语义加载（对齐交割单复盘「选中后照常平移」），不受游标窗口边界限制。

验收：

- 焦点态下向左/右平移能继续加载更早/更晚的 K 线
- 焦点态下平移**不会**把游标窗口的数据混进当前渲染数据集

## 非目标

- 不预填充缓存、不改变空洞的产生方式（按需回填照旧）
- 不改 `TradeChart` / 交割单复盘 / 个人交割单复盘
- 不改 10/28 舒适区跟随契约、不改 paper trading 领域逻辑
- 不加全局 error boundary（另议）

## 约束

- `orderFocus` 仍是临时 UI 状态，**不进** session 存盘协议
- 全量 `npm test` 通过、`npx tsc --noEmit` 干净
- 焦点态/非焦点态两条渲染路径都要有回归测试
