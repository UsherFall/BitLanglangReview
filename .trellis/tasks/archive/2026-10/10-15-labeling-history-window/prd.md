# 标注窗口扩到 1 年（含 Bitget 往前翻页能力）

> 依赖：无（本任务是基础能力）。
> 被依赖：`10-15-structure-fullness`（判据改「以大行情为分界」后，线上扫描窗口也要用这份翻页能力）。

## Goal

标注时图上只有 90 根日线，**看不出「上一段大行情」** —— 而这是用户判定结构饱满度的第一轴（2026-10-15：「大行情后面往往都是震荡，我们找的是震荡转大行情的机会」）。

本任务交付两件事：

1. **给 `BitgetCandleSource` 加往前翻页取长历史的能力**（含配套缓存策略）——`src/server` 的能力，后续扫描也复用它；
2. **标注页用这份能力显示 1 年**（约 365 根），判定输入**在本任务范围内**仍按线上当前口径（最新 90 根），保证候选集与线上可比。

## 触发 / 实测依据（2026-10-15 只读复核）

| 请求 | 实测结果 |
| --- | --- |
| Bitget `/candles` 1W limit=200 | **13 根**（≈90 天）—— 回溯窗口是**时间跨度**，不是根数；**周线信息更少，不是答案** |
| Bitget `/candles` 1D，`endTime` 往前挪 | 每次 90 根，可翻页；**能到 ≈2023-10** |
| Bitget `/history-candles` 1D，`endTime` 往前挪 | 每次 90 根；**能到 ≈2019-10** |
| `startTime`+`endTime` 跨度 89 / 91 天 | 89 天返回 89 根；91 天 `code=00001` 报错 → **跨度上限 90 天** |
| 限频 | 自设 `BITGET_MIN_INTERVAL_MS=50`（+10ms jitter）≈ **20 req/s**，正压实测名义上限 |

## Requirements

### R1 翻页取数能力（落在 `src/server`）

- **R1.1** `BitgetCandleSource` 支持按**回溯时长**取历史（1 年 ≈ 365 根），内部用 `endTime` 逐页前移，每页 ≤90 根；返回 0 根即停（次新币天然抓不满）。
- **R1.2 端点选择**：翻页页必须用 `/api/v2/mix/market/history-candles`（`/candles` 只回溯约 3 年）。
- **R1.3 缓存策略（关键）**：历史页是**不变数据**，必须进 `CandlestickStore` 并被后续读取命中；**只有最新一页参与刷新**。今天扫描是 `refresh: anchor === undefined` → 每轮全量重取；若照此翻页会每轮付 N 倍成本，必须一起改。
- **R1.4 限频不变**：沿用现有全局 pacer（20 req/s），不自作提高；429 走既有退避 + `warnings` 透出通道。
- **R1.5 行为向后兼容**：**线上扫描在本任务内不改变行为**（仍请求 90 根）；新能力只在被显式要求更长窗口时生效。

### R2 标注工具用 1 年

- **R2.1** 池阶段仍抓 90 根（与线上一致）→ 粗筛 + 检测器 → **决定候选集**；显示阶段仅对候选翻页抓 1 年。
- **R2.2 判定输入不变**：喂 `coarseStructure` / `probeStructure` 的仍是**最新 90 根原始 bar**，再按与线上相同的规则剔未收盘 bar。**不得**把长序列喂给判定器 —— 否则 `posRange` 会变，候选集与线上脱钩。
  > `structure-fullness` 会把这条改掉；在那之前，保可比是本任务的硬约束。
- **R2.3 快照瘦身**：bar 存紧凑数组 `[timestamp, open, high, low, close]`，去掉每根重复的 `instrument` / `timeframe` / `volume`。
- **R2.4 页面**：显示完整 1 年序列（升序、剔未收盘）；**标注交互一律不变**（`Y/N/?`、`←`、`S`、理由 `1`-`3`、localStorage 断点、导出字段与行数）。
- **R2.5 进度按 `anchor` 隔离**：新快照 = 新进度空间，旧导出不受影响。

### R3 边界

- 不动 `label-rubric.md` 的判定口径与理由集。
- 不把「大行情分段」的判据改动混进来 —— 那是 `structure-fullness`。
