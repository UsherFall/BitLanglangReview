# 设计：粗筛 → 标线 → 报警

## 1. 边界

```
┌─────────────────────────────────────────────────────────┐
│ 第 1 步  粗筛（算法）                                    │
│  输入：全池 1D 日线                                      │
│  输出：候选币 + 拉升区间                                  │
│  ⚠ 口径未定（见风险）                                    │
├─────────────────────────────────────────────────────────┤
│ 第 2 步  标线（用户，唯一信源）                           │
│  输入：第 1 步的图（可缩放、可画线、可备注）               │
│  输出：水平线 / 趋势线（射线），每币多条                   │
├─────────────────────────────────────────────────────────┤
│ 第 3 步  距线警报（算法，纯算术）                          │
│  输入：今日收盘、用户线、该币波动尺                        │
│  输出：距线 ÷ 尺子 → 报警 / 观察中 / 不接近                │
└─────────────────────────────────────────────────────────┘
```

三条铁律：

1. **第 1 步不产结论**，只给"这段拉了"。好不好不归它管。
2. **第 3 步只算距离**，不打分、不排序成推荐。
3. **收敛/股性/结构不归算法** —— 用户 10/20 第三次明确划线，对应上一轮 9 条判据类全败。

## 2. 数据流

```
Bitget API (1D, UTC 0点开盘)
    │
    ▼
fetch-pool.mjs ──→ research/pool/*.json  ([t,o,h,l,c,vol], 毫秒时间戳, ≥120根)
    │
    ├──→ build-annotate.mjs ──→ out/annotate-today.html  （第 2 步的入口）
    │
    │                          user draws lines in browser
    │                          (localStorage, no backend)
    │                              │
    │                              ▼
    │                      research/draw/labels.json   （用户导出后放这里）
    │
    └──→ alert.mjs ──→ out/alert.json               （第 3 步的产出）
```

**关键：线是唯一的耦合点。** 粗筛不用知道线，警报不用知道粗筛。

## 4. 第 3 步：距线警报

```
尺子 = 该币日内振幅中位数（%）
  用户画过射线 → 用"射线起点之后那段行情"的中位
  否则          → 用最近 60 根的中位

距线% = |收盘 - 线价| / 线价 × 100
倍数  = 距线% / 尺子

倍数 ≤ 0.5 → 🔔 报警
倍数 ≤ 1.0 → · 观察中
倍数 > 1.0 → 不接近（安静）
```

**尺子为什么自适应**（用户 10/20）：BTC 尺子 2.38%，山寨 6~8%。固定百分比会把 BTC 误报成"接近"。

### 实测（10 段标注回放）

| 命中区间末 | 晚 1~2 天 | 从未触发 |
|---|---|---|
| JST / BNB / LINEA / **ETH** / ZRX | BAND / APT | OPG / RENDER |

ETH 那段正好命中 08-17（你标的区间末），正是"收盘回到线上 +0.38%"。

### 现状（判定日 10-19）

| 警报 | 观察中 | 不接近 |
|---|---|---|
| LINEA / BNB / BAND / ZRX / JST | **BTC**(0.62×) / APT | RENDER / OPG / ETH |

BTC 安静地躺在观察中，符合用户"还没到"的判断。

## 5. 已证伪（本轮失败清单）

| 方案 | 结果 |
|---|---|
| 涨幅 20~80% 作粗筛条件 | 同涨幅 70~79%，OPG/ZRX/BAND/RENDER 会做、DOT/IO 没结构 |
| 「收回突破线上」当信号 | 用户：不用站上去，在附近就行 |
| 固定百分比"附近" | 1.5% 会误报 BTC |
| 拿今天价格比历史线 | 用户：扫的是标注区间那段时间，不是现在 |
| 数"第几次接近"才响 | 用户：不用这么复杂，画线后接近就报 |

## 6. 风险

| 风险 | 应对 |
|---|---|
| **第 1 步粗筛口径没定** | 现口径每天 208 个 ≈ 没筛；且 ETH 那种"提前判断"的段结构上扫不到 |
| 用户标注分散 | 9 个会做分布在离顶排序第 1~35 名，任何单维排序取前 20 最多覆盖 6/9 |
| 线在"画好的当天"就在价格附近 | 判定从线的第二个端点之后开始算（BTC 误报已修） |

## 7. 产品形态（等粗筛定了才做）

```
[今日]
  🔔 警报：价格回到你标的线附近     （n 个，通常 0~5）
  ·  观察中：线画好，还没接近      （m 个）
  —  不接近                       （其余，不显示）

[新增候选] ← 第 1 步的粗筛（今天的"新触发"）
```

**第 1 栏不设下限也不设上限**：它就是事件驱动，没变化就是空表。用户上限 20 个的约束针对的是**第 2 栏的"候选"**（标注页里今天要看的），不是警报。
