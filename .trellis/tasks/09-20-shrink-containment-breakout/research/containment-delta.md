**在榜币数与合格(币×周期)数只减少 1 个，包含性闸门从 0 次拒绝变为 103 次。**

| 指标 | 改动前 | 改动后 | 差值 |

| 合格(币×周期)数 | 46 | 45 | **−1** |

## 镜像忠实度交叉验证

逐条比对"真实 `detectConvergence`（改动后）"与"镜像 `excludeTail = 1`"的决策：

```
不一致条目 = 0 （完全一致，60 币 × 5 周期 = 300 条全部一致）
```

这条验证很重要：本次测量的"改动前"数字完全来自镜像，如果镜像不忠实，整份对照就没有意义。

## 与改动前基线的复测一致性

三次独立测量（行情实时变化，绝对值会漂移，看差值）：

| 测量 | 在榜币数（前→后） | 合格(币×周期)（前→后） | 包含性拒绝 |
| --- | --- | --- | --- |
| 规划期第 1 次 | 27 → 27（Δ0） | 44 → 43（Δ−1） | 107 / 2299 |
| 规划期第 2 次 | 27 → 27（Δ0） | 45 → 45（Δ0） | 98 / 2415 |
| 实现后（真实函数） | 29 → 28（Δ−1） | 46 → 45（Δ−1） | 103 / 2563 |

**Δ 稳定落在 {0, −1}**，与 `prd.md` AC4 声明的预期区间（在榜币数 27±1、合格数 44±2）一致。
`1D` 分周期合格数在留出 1 根时三次都为 **5 → 5（不变）**，只有留出 2 根以上才会掉到 4。

## 对"收益"的如实表述

本次修改**没有**让榜单明显变小，原因是 `design.md` / `containment-baseline.md` §5 已记录的：真正的突破早被**平坦度**闸门拦住了。包含性闸门补上的是：

1. **语义归属**——注释承诺的突破保护终于由包含性自己负责，而不是靠平坦度误打误撞；
2. **被测覆盖**——原有的闸门用例只在"不可能K线"上可达，现在有了合法K线的守卫；
3. **轻微突破的兜底**——103/2563（约 4%）的候选带在平坦度放行后被包含性拒掉。

# 附加测量：面板「位置」列的可见变化（check 阶段补测）

`position` 并非无消费者：`src/ui/CoinScanPanel.tsx:310` 把它经 `formatPosition`（`:362`）渲染成展开详情表里的「位置」百分比。
本次把 `position` 的区间从"整条带"改为"确认区间"后，**这个百分比会漂移**。实测（同一时点，合格行）：

| 指标 | 数值 |
| --- | --- |
| 前后都在榜的合格行 | 41 |
| 其中 `position` **未变**的行 | **36**（87.8%） |
| 其中 `position` **变化**的行 | **5**（12.2%） |
| 变化幅度（平均） | 1.37 个百分点 |
| 变化幅度（最大） | **25.4 个百分点** |
| 新增合格 / 掉出榜 | 0 / 2 |

变化最大的一行（面板显示值 = `position × 100`）：

| 品种:周期 | 旧显示 | 新显示 | Δ |
| --- | --- | --- | --- |
| CLUSDT:4H | 74.6% | **100.0%** | +25.4 |
| XAUUSDT:4H | 22.3% | **0.0%** | −22.3 |
| INJUSDT:5m | 93.0% | **100.0%** | +7.0 |
| ETHUSDT:1D | 88.0% | 88.9% | +0.9 |
| CAPUSDT:1D | 25.1% | 25.6% | +0.5 |

注意 `100.0%` / `0.0%` 这几行：最新一根越出了确认区间但仍在 10% 容差内，`clamp01` 把它压到端点。语义上是"贴着/略超上沿"，但显示成整 100% / 0% 可能被误读。

**结论**：前端代码零改动，但**有一处展示数字会变**——绝大多数行（36/41）不变，少数行（5/41，集中在 4H）会明显变化，个别会显示端点值。这个取舍需要明确确认（见 `prd.md` Open Questions）。
