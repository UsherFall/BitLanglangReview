# 标注页显示 90根位置/前戏幅度并支持排序；修理由串味

## Goal

285 条手工标签的分析结论是：**现有检测器 score 与用户判断反向**，而两个朴素客观量有明显信号。本任务把这两个量**显示在图上**并**支持按它们排序**，让人一眼看到"最像的"，同时修掉理由沿用的串味问题。

本任务**不改判据实现**（`src/domain/coin-scan.ts` 不动）—— 只改标注页的信息呈现。

## 触发 / 分析结论（2026-10-18，285 条手工标签）

| 判据 | 精确率 | 召回率 |
| --- | --- | --- |
| 检测器 `converged` | **8.6%** | 8.3% |
| 粗筛 `passCoarse` | 14.2% | 72.2% |

基线（随机）= 12.6%（36 Y / 249 N）。**`converged` 低于基线**；把 `score` 阈值调高，Y 占比反而下降（29.3%→14.0%→10.5%→6.9%）—— **排序方向是反的**。

有信号的两个量（阈值扫描 Y 占比）：

| 阈值 | `priorMove` | `pos90` |
| --- | --- | --- |
| 中位 | 17.5% | 18.2% |
| 80 分位 | 21.1% | **29.8%**（覆盖 47% 的 Y） |
| 90 分位 | 24.1%（覆盖 19% Y） | **31.0%**（覆盖 25% Y） |

## Requirements

- **R1 显示两个客观量**：页头在合约名旁显示 `90日位置 xx%` 与 `前戏 xx%`，随图切换刷新。定义写死并注释清楚：
  - `pos90` = `(最新收盘 − 最近90根最低) / (最近90根最高 − 最低)`，0 = 贴 90 根底部，1 = 贴顶部；
  - `priorMove` = `(close[-24] − close[-90]) / close[-90]`，即**最近 23 天之前的 67 根**的净位移（"前戏"幅度，带符号）。
- **R2 排序开关**：页脚加一个下拉，选项 `打散（默认）/ 按 90日位置 / 按 前戏幅度 / 按 score`。
  - 切换后**重置到第 1 张**（标签按 instrument 存，不丢），并在状态行说明已按什么排序、共几条。
  - `按 score` 保留但标注"（已知反向，仅供对照）"，避免以后又误用。
- **R3 修理由串味**：记录一条标签后**把理由与备注清空**。理由不再沿用到下一张——分析里出现 21 个 Y 带着「还没顺势」就是沿用造成的。
- **R4 数值在构建期算好**放进页面数据（不在浏览器里重算），并保留两位小数的百分比显示。
- **R5 边界**：不改 `src/`；不改导出 CSV 字段（`pos90`/`priorMove` 不进 CSV，避免与既有标签文件混格式）；不动采样与快照。

## Acceptance Criteria

- [ ] AC1 页头显示 `90日位置` 与 `前戏`，数值与构建期算出的值一致（抽 3 只比对）。
- [ ] AC2 四个排序选项都生效：切换后第 1 张的顺序符合该键降序；`打散` 回到原顺序。
- [ ] AC3 切换排序不丢标签：切换前后 localStorage 里的条数与内容不变，进度回到 `1 / N`。
- [ ] AC4 记录后理由下拉与备注框被清空（不会再出现 Y 带负向理由）。
- [ ] AC5 `npx tsc --noEmit` 与 `npm test` 全绿；`git status -- src/` 为空；内联 JS 过 `node --check`。
- [ ] AC6 jsdom 断言覆盖：显示、四个排序的头部元素、切换后 index 归零、标签保留、理由清空。
